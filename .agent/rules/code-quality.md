# Качество кода и проверки

- Используй понятные имена, простую структуру и существующие соглашения проекта. Не расширяй задачу ненужным рефакторингом.
- Явно обрабатывай ошибки; комментариями объясняй неочевидные решения.
- Добавляй или обновляй тесты, когда они помогают проверить важное поведение. Не выдавай ручную проверку или сборку за автоматические тесты.
- Для общей проверки запускай `npm run verify` (линтер, проверка типов и тесты); для проверки production-сборки — `npm run build`. Выбирай дополнительные проверки по характеру изменения. Если необходимую проверку выполнить не удалось, сообщи об этом и причине.
- Выбирай зависимости осознанно: проверяй необходимость, совместимость и влияние на проект.
