# Git

- Для новой задачи используй отдельную ветку от актуальной основной, если пользователь не попросил иначе; продолжение задачи выполняй в её ветке.
- Перед коммитом проверяй состояние и состав изменений; не включай секреты, локальные файлы окружения и результаты сборки.
- Используй настроенные имя и email владельца; не добавляй подписи или `Co-authored-by` от имени агента. Не меняй конфигурацию Git без просьбы.
- Пиши краткие сообщения коммитов на русском языке; допускается префикс Conventional Commits, например `fix: исправить вход`.
- Не переписывай опубликованную историю и не удаляй удалённые ветки без явной просьбы. Не переключай ветки так, чтобы потерять или смешать изменения пользователя.
- После завершения задачи отправляй ветку и открывай PR в основную ветку, если пользователь не попросил иного. Объединяй PR только после успешных обязательных проверок и проверки состояния веток; при конфликте или неуспешных проверках сообщай о препятствии.
